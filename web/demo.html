What happens to your drawing

The trained network, step by step. Each step updates live as you draw.

  1. The drawing becomes 28 × 28 pixels

    The network was trained on MNIST, a set of 70,000 handwritten digits, each 28 pixels square. Your drawing is cropped, scaled and centred the same way.

  2. Each pixel becomes a signed byte

    A pixel's brightness, 0 to 255, is stored as brightness − 128, a number from −128 to 127 that fits in 8 bits. Here is the middle row of your image as the chip would hold it:

  3. 128 neurons multiply and add

    Each neuron multiplies all 784 bytes by its own 784 learned weights and adds them up: 100,352 multiplications for this layer alone. Integer results are scaled back into 8 bits with an integer multiply and shift. Bright squares are neurons that respond to your drawing.

    A second layer turns the 128 neuron values into one score per digit. The highest score wins. These are the 8-bit scores the integer network produced:

Quantize

How few bits can a weight have?

Storing weights in 8 bits instead of 32 makes the model four times smaller (102 KB instead of 407 KB) and lets a small chip use cheap integer arithmetic. Push it further and the network eventually stops working. Try it on your drawing:

This experiment rounds the weights only and keeps the rest in floating point.

Silicon

The hardware: four multiplications per instruction

Almost all the work in step c above is multiply-and-add. A plain 32-bit RISC-V core multiplies one pair of numbers per instruction, but four 8-bit values fit in one 32-bit register. So I designed a unit, in Verilog, that multiplies four pairs at once and adds them to a running total in a single instruction, using an opcode RISC-V reserves for custom extensions.

Verified
25,088 test instructions from a real MNIST image, with 0 mismatches between the Verilog and the software model. The instruction decoder was checked on the same stream with 3,115 unrelated cycles mixed in: 0 mismatches.
Size and speed on an FPGA
4 DSP blocks, 33 lookup tables and 34 flip-flops on a Xilinx 7-series chip. After place and route: up to 47.0 MHz on a Lattice iCE40 UP5K and 68.7 MHz on a Lattice ECP5.
Measured speed-up
5.03× fewer instructions to classify a digit on a simulated RISC-V chip, with every output byte unchanged (below).

The instructions

InstructionWhat it does
simd_maczMultiplies four pairs and starts a new running total
simd_maccMultiplies four more pairs and adds them to the total
simd_mac_clr, simd_macThe first versions; simd_mac reads the total from a third register

A small processor reads two registers per instruction, not three. So the newer pair keeps the running total inside the unit, in the register that already holds its result. Measured on the iCE40: one extra logic cell, and no loss of clock speed.

RISC-V

Running on a RISC-V chip

The same integer network, compiled as bare-metal C for a 32-bit RISC-V processor (RV32IM) and run on Spike, the reference RISC-V simulator: no operating system, no floating point, no standard library. The firmware checks every output byte against the C++ engine.

Instructions to classify one digit

Plain RV32IM 818,683
With simd_mac_clr + add being measured
With simd_macz / simd_macc being measured

101,632 multiply-accumulates per digit, so plain RV32IM needs about 8.1 instructions for each one. With the new instructions the inner loop does four of them in six instructions: two loads, the MAC, two pointer steps and the loop branch. Spike counts instructions, not clock cycles; cycle-accurate numbers come from running the firmware on a real RISC-V core in simulation, the next step.
